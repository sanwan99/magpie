# ADR-0004: 本地数据加密与恢复设计

状态：**P2 设计提案，尚未实现、尚未选定加密存储实现**。2026-10-18。

本文不改变当前数据格式，不启用加密，不安装依赖，也不提供加密或恢复效果保证。
当前实现仍是未加密的 SQLite / FTS5 和 PNG 文件；现有认证锁是界面访问控制。
实际边界以 [SECURITY.md](../../SECURITY.md) 为准。
本提案延续 [ADR-0003](0003-privacy-and-release-boundaries.md) 的原生技术栈、可迁移数据格式和失败关闭原则。

## 目标与威胁边界

目标是在未解锁数据存储时，降低复制应用数据目录或备份后直接读取内容的风险，
同时保留历史、片段、图片、搜索和可验证的恢复能力。实现必须覆盖内容的所有持久化副本。
不能只把主表的 `payload` 加密，然后保留可读的标题、FTS 或图片。

| 场景 | 设计目标或边界 |
| --- | --- |
| 仅获得已关闭应用的数据目录副本 | 没有解锁材料时不能直接恢复受保护内容；通过真实文件审查和恢复测试验收 |
| 仅获得导出的加密备份 | 备份须独立验证完整性，并需要明确的恢复材料；不能把可直接解密的密钥与密文并排存放 |
| 当前登录用户下的恶意进程、管理员或已被控制的系统 | 不承诺抵御其读取已解锁进程、输入、系统剪贴板或用户操作；应在产品说明中保留此边界 |
| 应用已经解锁并显示内容 | 窗口、内存、复制/粘贴和用户主动导出需要明文；不能声称此时内容对同一用户不可见 |
| 用户原始文件、Finder 文件剪贴板和系统剪贴板 | 不属于 Magpie 加密容器；记录它们的路径和元数据属于受保护内容 |
| 旧版本生成的日志、明文数据库、快照和外部备份 | 新功能不能追溯消除这些副本；迁移与清理必须明确提醒用户 |

辅助功能、屏幕录制权限和面板 Touch ID 设置不等于数据加密授权。
本设计也不能替代剪贴板隐私标记、秘密启发式过滤、权限最小化或内容级日志禁令。

## 保护范围

| 数据 | 要求 |
| --- | --- |
| `clips` | 正文、标题、来源应用、原始路径、时间、标签、备注、置顶状态、去重索引一起纳入存储边界 |
| `clips_fts` 与内部索引页 | 搜索词、正文和索引副本与主库使用同等保护；不能将解密后的 FTS 留在磁盘 |
| `snippets` | 触发词、标题、正文及时间一起保护；解锁前禁用读取和自动展开 |
| 数据库关联文件 | 验证 WAL、journal、临时数据库、排序/临时文件、恢复文件和异常退出产物，不能只检查主文件头 |
| `images/` | 图片内容及敏感元数据使用带完整性验证的加密格式；文件名采用不含标题/路径的随机标识 |
| 图片缩略图、预览、OCR 和编辑中间产物 | 优先仅在内存中存在；若需要落盘，必须进入同等保护的临时存储，并有退出/崩溃后的清理策略 |
| 备份、迁移暂存和导出 | 根据下文单独设计，不能默认压缩包或应用包签名等同于内容加密 |
| 设置 | 先盘点忽略应用列表、近期路径等是否敏感。非敏感偏好可以保留原位置，敏感项必须迁入保护边界或明确列为泄露元数据 |
| 日志、错误、遥测 | 保持固定事件与数字错误类别，不输出密钥、内容、恢复短语、SQL 参数或内部解密异常详情 |

现有 PNG 路径和读取接口不能假装继续读取加密文件。需要独立的图片读取边界，
在授权状态下解密后供现有 SwiftUI/AppKit 渲染使用，避免为兼容旧接口永久写出明文 PNG。
大图解码、临时内存和截图编辑器的峰值占用须单独测量。

## 密钥和解锁生命周期

拟采用每个数据存储独立的随机数据密钥，使用经过审查的加密实现。
数据库、图片和备份的密钥隔离、派生方式、随机数、nonce 规则及认证元数据属于待验证设计；
不自行实现密码学算法，不重复使用要求唯一的 nonce，也不通过日志排查密钥内容。

Keychain 是本提案的本机密钥保护候选边界。具体条目类型、访问控制、认证提示、
签名身份要求、可用性和设备迁移行为必须在实现前根据 Apple 官方文档和实机结果确定。
**本提案不假设 Keychain 条目一定随设备迁移、系统恢复或账户变化而可用。**

- 主密钥不写入 UserDefaults、仓库、环境变量、普通配置文件或诊断附件。
- 磁盘容器仅保存非秘密的格式版本、随机存储标识、密钥版本和必要的加密参数。
  标识须参与完整性校验，不能被替换来混用其他用户或其他存储的图片。
- 用户认证与实际取钥必须形成一致的授权流程。不能先弹出一次“认证成功”，
  再从无保护的文件中取得密钥并把两者宣传为强访问控制。
- 密钥不可用、认证取消、权限不满足或完整性校验失败时停止读取和录入受保护数据；
  显示可恢复的状态，不自动新建空库覆盖原库，也不退回明文存储。
- 明确区分“关闭面板”与“锁定数据存储”。若关闭面板即丢弃解密能力，后台记录也必须暂停；
  若后台记录继续，界面必须说明密钥仍可用于运行中的存储，不能声称磁盘容器已锁定。
- 睡眠、锁屏、会话切换、重新登录及退出时的锁定策略必须同时覆盖数据库连接、
  解密图片缓存、搜索结果、OCR 结果和片段展开。异步旧结果不可重新显示内容。
- 释放密钥与缓存是生命周期要求，不宣称能证明 Swift/AppKit 的所有内存副本已被安全擦除。

数据密钥轮换必须有版本和可恢复步骤。旧密钥只有在所有仍需恢复的数据库、图片和备份
都有验证过的替代恢复路径后才能退役；不能为了完成轮换而使已有备份无声失效。

## 从现有明文数据迁移

这不是一次简单的 `ALTER TABLE`。跨数据库、图片和密钥的切换需要独立迁移协调，
同时保留既有 GRDB schema migrations 的可重复执行语义。

1. **预检和说明**：识别原格式/版本，检查可用空间与目标目录权限，列出将处理的数据，
   告知明文源与旧备份可能继续存在。用户决定是否开始迁移及保留恢复副本。
2. **形成一致源状态**：暂停 watcher，失效排队快照，等待进行中的写入、图片操作和清理结束。
   使用经过验证的一致备份/关闭流程，不能直接复制正在变化的 SQLite 主文件而忽略 WAL。
3. **建立独立目标**：保留源不变，在同一受控区域创建有版本标记的目标存储和迁移状态记录。
   密钥必须先能够重新取回并通过小型读写验证，才能开始大规模转换。
4. **分批复制与核对**：迁移正文、片段、原有 ID、置顶、备注、标签、来源、时间及图片引用。
   在加密边界内重建 FTS，核对记录数、实际内容、搜索结果与图片解码；迁移过程不输出内容。
   每批进度可恢复，不能仅因为文件存在就视为已经迁移成功。
5. **重新打开验收**：关闭目标并通过正常启动路径重新解锁、打开与查询。
   验证失败则继续保留源，目标不得成为用户唯一的数据副本。
6. **切换活动存储**：只有目标完整验证后才能提交活动存储的切换。
   切换协议、同卷文件操作和断电恢复语义需要实测；不能宣称跨多个文件和 Keychain 操作天然原子。
7. **保留恢复能力**：清楚列出旧明文源、暂存目录和备份的位置、保护状态与后续选择。
   本实现不得未经用户授权删除它们，也不能承诺普通删除会安全擦除磁盘或快照中的内容。

迁移状态至少需要区分未开始、复制中、验证中、待切换、已切换和需要人工恢复。
状态记录只存版本、随机标识和进度，不存正文或密钥。每一步都要有故障注入测试。
异常重启时选择已验证的有效存储；不根据文件修改时间猜测哪一份是唯一正确副本。

失败回滚应恢复旧活动存储和录入策略，而不删除唯一有效副本。
若新版已成功写入加密存储，回退旧应用不等于数据库降级；此时不得自动启动旧明文副本
形成两个分叉历史。恢复工具应明确选择数据源，必要时通过经过验证的导入流程合并。

## 备份、丢失密钥与设备迁移

加密存储至少需要两种清晰区分的恢复入口：本机恢复、跨设备恢复。
不能把“备份了密文文件”描述为“已经具备可恢复备份”。

- 本机备份记录所需密钥版本，并验证实际解锁与恢复结果；不假设以后仍能取得 Keychain 条目。
- 跨设备备份需要用户明确选择的独立恢复方式，例如由独立恢复材料保护的密钥封装。
  具体算法、口令派生成本、格式和交互均待选型与测试，不在此预设实现。
- 恢复材料不得以可直接解密的形式嵌入同一备份。用户必须有机会验证已保存的恢复材料，
  并了解“忘记恢复材料且无法取得本机密钥”可能意味着无法恢复历史。
- 不设置维护者后门、固定恢复密钥或从账户身份推导出的秘密。若有效密钥全部丢失，
  应保留密文以便用户以后找到恢复材料，提供诊断与重新建库选项；不自动清空原数据。
- 恢复先写独立目录，验证备份完整性、格式兼容性、记录与图片引用后再切换。
  错误口令、缺失图片、损坏块、旧密钥或不支持版本不得覆盖现有工作数据。
- 必须实际验证新设备导入、系统重装、登录账户变化、签名身份变化和 Keychain 不可用等场景。
  不能仅用同一开发机上备份后立刻恢复的结果代替这些场景。
- 明文导出是显式用户操作，应提示导出内容失去容器保护；临时导出与用户正式保存的文件
  需要不同的保留策略，不在后台静默生成长期可读副本。

备份清单应明确包含哪些数据、格式版本和所需恢复材料，避免泄露原始文件名、剪贴板标题等信息。
清空历史的现有语义仍要明确区分片段、系统剪贴板、原始文件、应用备份与数据备份。
即使未来支持删除密钥，也不能据此声称所有历史明文、备份和缓存都已安全擦除。

## 尚未决策的实现选型

| 决策 | 必须取得的证据 |
| --- | --- |
| SQLite 整库加密或其他封装方式 | 保留 GRDB + SQLite + FTS5；覆盖 WAL/临时文件；能处理崩溃恢复、旧 schema 迁移及正常查询 |
| 应用层字段加密是否可行 | 若 FTS、元数据或排序仍落明文则不满足本设计；任何替代搜索方案需测量功能与性能代价 |
| 图片和备份格式 | 带完整性验证、版本升级、密钥隔离、流式/分块恢复、损坏检测，以及有明确边界的大图内存行为 |
| Keychain 项目配置 | macOS 14+ 的实际支持、锁屏/重启、签名变更、认证取消、设备迁移和不可用状态；查阅并引用官方文档 |
| 后台记录与解锁体验 | 面板关闭后是否继续录入、锁屏后是否暂停、自动恢复条件；产品文字必须与密钥生命周期一致 |
| 第三方实现或额外构建依赖 | 先证明必要性，再审查维护状态、许可证、供应链、GRDB 兼容性和发行构建；本提案不批准新增依赖 |
| 恢复口令/恢复材料 | 用户能完成保存与核验；失去材料时的结果明确；成本参数、格式与兼容策略可版本化 |

当前阶段只记录方案和验收门槛。具体 API 行为、密码学参数与候选依赖的适用性必须在
后续实现提案中引用相应官方资料或可重复实验，不把未经核实的行为写进用户承诺。

## 实施前验收清单

- [ ] 通过安全评审确定密钥获取、加密格式和威胁模型；独立于界面认证测试。
- [ ] 对 v1–v5 和后续实际发布的明文 schema 建立磁盘迁移样本，覆盖图片、FTS、片段、备注、置顶及中文搜索。
- [ ] 在每个迁移/切换步骤注入取消、权限失败、磁盘满、进程终止、目标损坏和密钥不可用；证明源数据不会被覆盖丢失。
- [ ] 使用合成敏感标记检查主库、FTS、WAL、journal、临时文件、图片、缩略图、备份和诊断产物；记录可见的元数据。
- [ ] 对密文截断、篡改、错误密钥、错误版本与存储间文件替换验证失败关闭和可恢复提示。
- [ ] 验证锁屏/睡眠/重新登录期间的密钥、缓存、后台录入、截图和 Snippet 行为；检查异步旧结果。
- [ ] 在 1,000 / 10,000 / 50,000 条历史和大图样本上记录迁移耗时、搜索延迟、峰值内存、磁盘占用及失败恢复时间。
- [ ] 在独立测试账户或另一设备上完成备份恢复演练，包括丢失本机 Keychain、缺失恢复材料和错误材料。
- [ ] 保持现有未加密用户数据可读且迁移可选；新旧格式识别清晰，不能静默降级回明文。
- [ ] README、SECURITY、安装/升级说明、恢复说明和人工验收单同步更新，并明确仍无法保证的保护范围。

只有实现、迁移与恢复证据都通过验收后，才能在 README 或发行说明中将“加密存储”列为已实现功能。
